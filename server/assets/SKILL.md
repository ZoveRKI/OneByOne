# 生成改动讲解（OneByOne）

OneByOne 的命令行程序是 `{{ONEBYONE}}`。按顺序执行下面的步骤，所有命令都在当前项目目录里运行。

## 1. 切分改动

```bash
{{ONEBYONE}} hunks
```

- 默认对比 HEAD 和工作区，包括未提交和未跟踪的文件。
- 用户想看某个提交之后的全部改动：加 `--base <提交>`；比较两个提交：`--base <A> --head <B>`；只看部分目录：在最后加 `-- <路径>`。
- 如果输出"没有发现改动"，告诉用户并结束。

## 2. 阅读改动清单

读取 `.onebyone/hunks.md`，内容较长时分段读。结合本次对话里你对这些改动的了解（为什么改、当时怎么考虑的），讲解会准确得多。

## 3. 写讲解步骤

按 `hunks.md` 末尾的「写法要求」写 `.onebyone/steps.json`。只写步骤和讲解，引用改动块的 id，不要复制代码。

## 4. 生成并检查

```bash
{{ONEBYONE}} build
```

退出码不是 0 时，按输出的提示修改 `steps.json` 再运行，直到显示"讲解覆盖了全部改动块"并且没有数据问题。不要为了通过检查而把无关的改动塞进不相关的步骤，应该如实单独说明。

## 5. 打开播放器

```bash
{{ONEBYONE}} open
```

它会用浏览器打开 `.onebyone/walkthrough.html`，命令本身马上结束。把页面路径告诉用户，再用两三句话概括这次改动分成了哪几部分。

`.onebyone/` 是生成目录，里面自带 `.gitignore`，不会进入提交。
